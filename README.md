# ClarifAI

ClarifAI turns a one-line software project idea into a full IEEE-style Software Requirements Specification (SRS). It generates clarification questions tailored to the specific project described, then uses Google Gemini to produce functional requirements, user stories, acceptance criteria, MVP scope, and AI-driven recommendations.

**Live demo:** https://clarif-ai-six.vercel.app
**API:** https://clarifai-backend-2ea0.onrender.com (health check: [`/health`](https://clarifai-backend-2ea0.onrender.com/health))

> The backend runs on Render's free tier, so it sleeps after inactivity. The first request after a pause can take 30-60 seconds while it wakes up.

## Tech Stack

| Layer    | Technology                                                        |
|----------|-------------------------------------------------------------------|
| Backend  | FastAPI, SQLite, JWT auth (PyJWT), Argon2 password hashing, Google Gemini (`google-genai` SDK) |
| Frontend | React 19, Vite, Tailwind CSS, React Router, react-markdown        |
| Hosting  | Render (backend), Vercel (frontend), Docker Compose (self-hosted option) |

## Features

- AI-generated clarification questions specific to the entered project idea, with a standard fallback question set if generation fails
- Full 9-section IEEE-style SRS generated by Gemini
- Refine a generated report with plain-language instructions
- Save, browse, and revisit past reports (per user account)
- Export reports as PDF, Markdown, or print
- JWT-based authentication
- Per-IP rate limiting on AI endpoints to protect free-tier API quotas

## Getting Started (Local Development)

### Prerequisites

- Python 3.11+
- Node.js 20+
- A free Gemini API key from https://aistudio.google.com/apikey

### Backend

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env
```

Fill in `.env`:

| Variable | Description |
|----------|-------------|
| `GEMINI_API_KEY` | Your Google AI Studio API key |
| `GEMINI_MODEL` | A currently supported Gemini model name (check AI Studio for available models) |
| `JWT_SECRET_KEY` | A long random string (32+ characters). Generate one with `python -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `ALLOWED_ORIGINS` | Comma-separated list of allowed frontend origins, e.g. `http://localhost:5173` |
| `RATE_LIMIT_MAX_REQUESTS` | Optional. Default `20` requests per window on AI endpoints |
| `RATE_LIMIT_WINDOW_SECONDS` | Optional. Default `3600` |
| `DATABASE_PATH` | Optional. Path to the SQLite file. Defaults to `backend/clarifai.db` |

Run the server:

```bash
uvicorn app.main:app --reload
```

The API is available at `http://127.0.0.1:8000`, with interactive docs at `http://127.0.0.1:8000/docs`.

### Frontend

```bash
cd frontend
npm install
cp .env.example .env
npm run dev
```

`.env` needs one variable:

```
VITE_API_BASE_URL=http://127.0.0.1:8000
```

The app is available at `http://localhost:5173`.

## API Overview

| Method | Endpoint            | Auth | Description                                   |
|--------|---------------------|------|-----------------------------------------------|
| POST   | /auth/signup        | No   | Create an account                             |
| POST   | /auth/login         | No   | Log in, receive a JWT                         |
| POST   | /questions/generate | No   | Generate project-specific questions           |
| POST   | /clarify/           | No   | Generate an SRS from answers                  |
| POST   | /clarify/refine     | No   | Refine an existing report with an instruction |
| POST   | /reports/           | Yes  | Save a generated report                       |
| GET    | /reports/           | Yes  | List saved reports                            |
| GET    | /reports/{id}       | Yes  | Fetch a single saved report                   |
| GET    | /health             | No   | Health check                                  |

The AI endpoints (`/questions/generate`, `/clarify/`, `/clarify/refine`) are rate limited per IP.

## Deployment

This project is deployed with the backend on Render and the frontend on Vercel. Both run on free tiers.

### Backend on Render

The repository includes a [`render.yaml`](./render.yaml) blueprint.

1. In Render, choose **New → Blueprint** and connect this repository.
2. When prompted, provide:
   - `GEMINI_API_KEY`
   - `GEMINI_MODEL`
   - `ALLOWED_ORIGINS`: your deployed frontend URL, with no trailing slash (for example `https://your-app.vercel.app`). Multiple origins can be comma-separated.
3. `JWT_SECRET_KEY` is generated automatically by the blueprint.
4. After the deploy finishes, open `<your-service-url>/health`. It should return `{"status":"ok"}`.

Manual setup, if you prefer not to use the blueprint: create a Web Service with root directory `backend`, build command `pip install -r requirements.txt`, start command `uvicorn app.main:app --host 0.0.0.0 --port $PORT`, and the same environment variables as above.

### Frontend on Vercel

1. Import the repository in Vercel.
2. Set **Root Directory** to `frontend` and the framework preset to **Vite**.
3. Build command: `npm run build`. Output directory: `dist`.
4. Add the environment variable `VITE_API_BASE_URL` set to your Render backend URL (no trailing slash).
5. Deploy. The included [`frontend/vercel.json`](./frontend/vercel.json) rewrites all routes to `index.html` so React Router works on page refresh.

`VITE_API_BASE_URL` is baked in at build time, so redeploy the frontend after changing it.

### Connecting the two

The backend only accepts requests from origins listed in `ALLOWED_ORIGINS`. After deploying the frontend, set `ALLOWED_ORIGINS` on Render to the exact Vercel URL. If signup, login, or question generation fails in the browser with a CORS error, this setting is the first thing to check.

### Self-hosted alternative: Docker Compose

```bash
cp backend/.env.example backend/.env
# edit backend/.env, and set ALLOWED_ORIGINS to the URL you will open the app at
export VITE_API_BASE_URL=http://YOUR_SERVER_IP:8000
docker compose up --build -d
```

This builds the backend and an nginx-served static frontend. The frontend is served on port 80 and the API on port 8000. The SQLite database persists in a named Docker volume across restarts.

## Troubleshooting

| Symptom | Likely cause |
|---------|--------------|
| "Couldn't reach the AI service" or signup/login fails on the deployed site | `ALLOWED_ORIGINS` on the backend doesn't match the frontend URL (CORS), or `VITE_API_BASE_URL` was missing when the frontend was built. Fix and redeploy. |
| "Using standard questions" notice | Gemini generation failed. Check `GEMINI_API_KEY` and `GEMINI_MODEL`, and the backend logs. |
| First request is very slow | The free Render instance was asleep. Wait up to a minute. |
| 429 "Too many requests" | You hit the per-IP rate limit. Wait, or raise `RATE_LIMIT_MAX_REQUESTS`. |
| Saved reports or accounts disappeared after a deploy | Render's free tier has an ephemeral disk, so SQLite data is reset on redeploy. |

## Known Limitations

- SQLite on Render's free tier does not persist across deploys or restarts. It is fine for a demo or portfolio. For persistence, use a paid disk or migrate to a hosted database such as Postgres.
- SQLite is not suited to multi-instance horizontal scaling.
- The rate limiter is in-memory: it resets on restart and, behind a proxy, may see the proxy's IP rather than the client's.
- JWTs do not support refresh. Sessions expire after 60 minutes.
- No automated test suite yet.
